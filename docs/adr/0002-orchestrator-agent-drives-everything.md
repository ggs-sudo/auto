# The orchestrator agent drives everything; driven sessions stay harness-agnostic

ADR-0001 put the driven session on the calling side: `report` as its mandatory final act, blocking `ask` for its questions. We reversed that. The harness drives **stock** Matt Pocock skills that know nothing about it and were never written for it, so a contract they must honour is a contract they will silently drop — and the two things the harness most needs are exactly the things a session-side contract cannot deliver: **verification** that a session persisted the tracker files it owes (skills forget), and **translation** of those tracker files into an execution graph (a judgment over files, not a value a session can return). So the MCP tools move to the orchestrator agent, which reads a session's trace at each stale point and lands its judgment as validated state: `send_to_session`, `complete_node`, `emit_graph`, `prototype_ready`, `fail_node`. Driven sessions get no harness tools at all and are never told the harness exists.

## Consequences

- **Nothing is asked of a session up front.** A dispatch is the skill invocation and its ticket, full stop — no injected obligations, no altered skills, no altered system prompts. The corollary is that any obligation the harness holds must be checkable *after* a turn has ended, which retires "claim the ticket before starting work" as something the harness can require, and makes an extra nudge cycle on skills with no tracker awareness of their own (`research`, `prototype`) a standing running cost rather than a defect.
- **Sessions persist, the orchestrator verifies.** A session that ends without writing its tracker files is nudged, up to three times, then failed. The orchestrator never writes a tracker file itself — including for gated work, which is why a session waiting on a human stays alive and idle rather than exiting.
- **The orchestrator agent's prose is never load-bearing.** Every effect is a tool call; zero tool calls means "still working, keep watching". An orchestrator agent that rambles can fail to act but cannot corrupt state.
- **The agent is ephemeral** — a fresh one per intervention, never one per run. A long-lived agent would accumulate every node's context and could not monitor parallel nodes.
- **`ask` and `report` are gone.** Detecting that a session asked a question is now the orchestrator agent's judgment over the trace, not a tool call — which is what lets the harness answer questions the skills pose in plain prose, as they naturally do headless where `AskUserQuestion` is unavailable.
